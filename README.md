# Kaijuclub

Automotive portfolio for drift, stance, track and street. A late-90s automotive magazine direction with chrome lettering, dark photography, bone-white editorial sections, racing-red accents and locally bundled fonts. The visitor can explore stories, disciplines, visual essays and detailed vehicle dossiers without leaving the site. The only social link is Instagram in the footer.

**Live:** https://alldaydigital.github.io/Kaijuclub_kc/

**Wagenbeheer:** [Instructions and management links](WAGENBEHEER.md)

The requested visual references are Nightride, Revved and Ultrace. Their current sites could not be inspected because external access was blocked. The reference photos are stock examples, explicitly disclosed, with provenance in [PHOTO-SOURCES.md](public/images/PHOTO-SOURCES.md). No owner names, specifications or events were invented.

## Development

Node.js 24 and Python 3.12+ are used in CI. Install the locked frontend dependencies and the pinned image-validation dependency:

```sh
npm --cache /tmp/kaiju-npm ci --no-audit --no-fund
python3 -m venv .cms-venv
.cms-venv/bin/python -m pip install --requirement scripts/cms-requirements.txt
npm --cache /tmp/kaiju-npm run dev -- --host 0.0.0.0 --port 5173
```

## Validation and production

```sh
.cms-venv/bin/python -m unittest discover -s tests -p 'test_vehicle_cms.py' -v
npm --cache /tmp/kaiju-npm run build -- --base=/Kaijuclub_kc/
npm --cache /tmp/kaiju-npm run preview -- --host 0.0.0.0 --port 4173
```

`deploy-pages.yml` publishes source pushes to main. `manage-vehicles.yml` validates authenticated GitHub Issue Form records, downloads and validates photos, builds before committing the catalog, and publishes the site in the same workflow. It uses the server-side `GITHUB_TOKEN` supplied by GitHub Actions; no extra CMS secret or browser token is needed. Both workflows serialize deployments with the same concurrency group. Normal management runs publish even when the catalog is unchanged, allowing deployment failures to be retried.

`public/data/vehicles.json` is generated by `scripts/sync_vehicles.py`. It starts in reference mode and permanently switches to managed mode when an authorized club fiche exists. Concept and closed fiches are excluded, and an empty managed collection never restores demonstration cars. Photos are stored by checksum under `public/images/vehicles/<issue>/`. A failed validation retains the last valid catalog. Existing media is retained to avoid destructive cleanup.

The production build embeds the validated catalog for immediate rendering and also fetches the same-origin catalog. The first published club photo becomes the hero. Public CMS entries are escaped before display, and direct build URLs work under the GitHub Pages subpath.

## CMS tests

The unit suite checks publishing permissions, public contributor exclusion, draft/archive behavior, deterministic and atomic catalog writes, real JPEG/PNG/WebP decoding, corrupt or excessive images, restricted photo URLs and unavailable permission checks. It runs without credentials or network access.

For an actual authenticated integration check, create a clearly marked fiche with both `wagen` and `cms-test`, then dispatch `manage-vehicles.yml` with its number in `test_issue`. It validates the complete authorization and GitHub-upload download path, and saves a validation artifact without modifying or publishing the site. Ordinary runs always exclude these test records.

## Standalone preview

```sh
python3 scripts/export-preview.py
```

`dist/kaijuclub-preview.html` embeds fonts, photos, catalog and interactions for offline review. It is an exported artifact, not a hosted site. Avoid sharing localhost URLs as public previews.

GitHub Pages uses **Settings → Pages → Build and deployment → Source: GitHub Actions**. A deployment is live only after the workflow succeeds and the public HTTPS site has been checked.
